1. WHAT IS STELLA LOGOS?
────────────────────────────────────────────────────────────────────────────────

Stella Logos ("Star of Knowledge") is a professional-grade Educational
Management and Gamification Platform for secondary schools. It converts
traditional curriculum content into a visual, quest-based progression system.

The core idea: instead of "lessons," learners engage with "Learning Tasks" —
multi-step sequences tracked by a live database coordinate (CurrentStep). A
teacher can see exactly where every student is "stuck" in real time.

Three product pillars:

  A. QUEST-BASED PEDAGOGY
     - Learning Tasks are broken into steps. A learner advances one step at a
       time. A "Wait-State" guard prevents skipping ahead.
     - Each step advancement awards points and logs an xAPI statement.

  B. TEACHER THEATRE MODE (Phase 5 — not yet built)
     - Grid Monitor: live pulsing progress bars for every student.
     - Active messaging: tiled chat windows filtered by student step.

  C. PIXEL-ART ECONOMY (Phase 6 — not yet built)
     - Completing steps awards points. Points are spent in the Asset Shop on
       cosmetic skins (badges, avatars, profile themes).
     - Skins dynamically inject CSS variables, changing the learner's UI.

3. THE THEME SYSTEM (critical concept — read carefully)
────────────────────────────────────────────────────────────────────────────────

The entire visual identity of the app is controlled by a folder-based theme
system. Switching themes swaps assets and CSS variables — zero logic changes.

FOLDER STRUCTURE:
  /public/assets/themes/[theme-name]/
    ├── [page-name]/
    │   ├── background.png        ← full-screen page background
    │   ├── sprites.json          ← sprite manifest for this page
    │   └── sprites/
    │       ├── stationary/       ← fixed frame-animated sprites (torches, fire)
    │       └── moving/           ← travelling sprites (creatures, clouds)
    ├── banner_top.png            ← top header bar (shared across pages)
    ├── frame_main.png            ← 9-slice parchment/panel frame
    ├── btn_primary.png           ← primary action button texture
    ├── ambient_sprite.png        ← decorative side elements
    ├── input_box.png             ← input field background texture
    ├── music/theme.wav           ← looping ambient music track
    └── theme_map.txt             ← standard → aesthetic name registry

THREE THEMES REGISTERED: medieval, scifi, modern
  - medieval: fully built (pixel-art castle/dungeon aesthetic)
  - scifi: folder scaffolded, assets not yet created
  - modern: folder scaffolded, assets not yet created

HOW BACKGROUNDS LOAD:
  Each page calls usePageBackground('page-name'). This hook probes
  /assets/themes/{theme}/{page}/background.png and sets it as the body
  background. On unmount it clears, falling back to the CSS variable default.

HOW SPRITES WORK:
  SpriteManager reads sprites.json for the current page and theme. It renders:
    - frame_loop: LoopingSprite — fixed position, cycles through frame_1/2/3.png
    - random_flight: AnimatedSprite — creature that flies random waypoints
    - linear_drift: CSS keyframe animation (clouds)
  Sprites can be anchored to: background, top_header, or safe_zone.
  Missing assets fail silently (probe → display:none).

PERFORMANCE TIERS (via Network Information API):
  - High (4G, no saveData): all animations, sprites, preloading enabled
  - Low (3G/saveData): animations reduced, sprites filtered, hover-only preload

4. NAMING CONVENTION (must follow this)
────────────────────────────────────────────────────────────────────────────────

Every component uses a two-layer naming pattern:

  FunctionalName [AestheticName]

  - Bold/code names = the functional layer (stable, theme-neutral)
  - [Bracket] names = the medieval theme skin (can be swapped)

Examples:
  HomeCrossroads        [The Town Square]
  AttendenceUI          [The Tavern]
  QuestScreen           [The Quest Path]
  CurriculumNavigator   [The Royal Library]
  ShopUI                [The Merchant's Stall]
  SocialUI              [The Messenger Bird]
  GreatPortal           [The Great Portal]       — primary CTA button
  SmartContainer        [The Scroll Rack]        — accordion overlay panel

RULE: Code is always written against the functional name. The [Aesthetic]
name only appears in UI copy, asset paths, and theme_map.txt. Never write
medievalScrollFrame in a store, resolver, or prop name.

Database columns, GraphQL fields, Zustand keys, and React props must all be
theme-neutral (e.g. currentStep, pointsBalance, advanceStep).

9. KEY ARCHITECTURAL PATTERNS
────────────────────────────────────────────────────────────────────────────────

  THEATRICAL LAYOUT
    Every page: <div className="theatrical-container"> wraps the full viewport.
    Inside: <motion.div className="safe-zone"> holds all interactive content
    (max-width constrained, centred). Background fills the theatrical-container
    via CSS body backgroundImage. Sprites are position:absolute inside the
    theatrical-container (zIndex 1 for background anchor).

  PAGE ENTRANCE ANIMATION
    Every page's safe-zone uses:
      initial={{ opacity: 0, y: 16 }} animate={{ opacity: 1, y: 0 }}
      transition={{ duration: 0.45, ease: 'easeOut' }}

  SMART CONTAINER (AttendenceUI)
    A reusable accordion component. Collapsed state = 52px bar with title +
    preview text + ▶ arrow. Expanded state = full-screen fixed overlay
    (AnimatePresence scale-in modal, zIndex 60). Only one open at a time
    (controlled by entryStore accordion).

  BACKGROUND PRELOADING
    useBackgroundPreloader hook:
    - High tier: preloads all 6 page backgrounds on ProtectedLayout mount
    - Low tier: exposes preloadPage(page) called on tile hover in HomeCrossroads
    Module-level Set deduplicates — no double-fetching.

  ACADEMIC DAY CALCULATION
    CYCLE_REF = Monday 27 April 2026 = Day 1
    getAcademicDay(date): counts school days (skip Sat/Sun) from reference,
    applies modulo 10, returns 1-10.
    getSchoolDay(index): projects forward index school days from today,
    skipping weekends.

  SPRITE MANIFEST (sprites.json)
    Each page/theme folder has sprites.json:
    { "sprites": [{ "id", "file", "anchor", "position": {x%, y%},
      "size": {width%, height%}, "movement": { "type", "frameRate" } }] }
    Positions and sizes are percentage strings tunable without code changes.

  APPHEADER BANNER
    Probes banner image per route. Dynamic routes handled by extracting the
    first path segment: pathname.split('/')[1]. /submit maps to attendence.

  MUSIC SYSTEM
    ThemeMusicController mounts once in BrowserRouter. Audio element is a
    module-level singleton (survives route changes). Fades in on / and /home,
    fades out on all other routes. MusicToggle available in header and login.

11. IMPORTANT CONVENTIONS FOR AI AGENTS
────────────────────────────────────────────────────────────────────────────────

  - DO use the Functional [Aesthetic] naming pattern (see Section 4).
  - DO write all new pages with the theatrical-container + motion.div
    safe-zone pattern and the standard entrance animation.
  - DO add new sprite types to sprites.json — never hardcode sprite positions
    in TSX. Position and size must be tunable via the JSON.
  - DO keep mock data in mockState.ts until the DB connection phase.
  - DO follow the per-page asset folder convention for any new page:
      public/assets/themes/medieval/[pagename]/background.png
      public/assets/themes/medieval/[pagename]/sprites.json
      public/assets/themes/medieval/[pagename]/sprites/stationary/
      public/assets/themes/medieval/[pagename]/sprites/moving/
  - DO add new routes to AppHeader.tsx routeToPage map.
  - DO add new pages to useBackgroundPreloader ALL_PAGES array.
  - DON'T add theme-specific strings to stores, resolvers, or prop names.
  - DON'T create new Zustand stores for things that are only needed locally
    — use component useState instead.
  - DON'T connect to the database for screens that are still on mock data.
    Keep the boundary clean.
  - The spelling "attendence" (with an e) is intentional and used consistently
    throughout the codebase (routes, folder names, component names). Do not
    correct it.
